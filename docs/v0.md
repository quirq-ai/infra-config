# quirq infra v0: a base version of every repo, end to end on GitHub

> **Reference copy.** The v0 version plan as of 2026-10-03, copied here so that v0 sessions can read it. suraj keeps the original; if the two differ, the original wins. Two edits were made: the link to the overview points at [plan.md](plan.md), and one local file path became a description. v1.md and v2.md are not copied, so links to them do not resolve here.

Status: version plan, drafted 2026-10-03 from [plan.md](plan.md) (the overview).
Next: [v1.md](v1.md), then [v2.md](v2.md).

**Goal.** Every one of the thirteen infra repos exists, is public, sits behind its own gate and does a
first, thin version of its job. The toolchain works end to end on GitHub: a change to a product repo
is built from its manifest, gated on the exact merge result, watched after it lands, and shipped to
the canary channel by agents every day. (Decisions D1–D15 in plan §10.1.)

**Scope rules for v0.**
- Product kinds: latest stable Python and latest stable Next.js only (D1). Containers and docs-only
  kinds come in v1. xo-space targets Python 3.12 today (its `tests.yml` and Dockerfile), docs pins
  `next` 16.2.4 and innernet `^16.3.8`, so "latest" means a pinned toolchain that rollers keep current
  [inf]. On 2026-10-03 the latest stable releases are Python 3.14.8 and Next.js 16.3.8; Python 3.15.0 is
  due 2026-10-09 (PEP 790) **[cr]**.
- Public repos only (D2). First product repos: xo-space (`python-service`) and innernet (`node-app`,
  Next.js), the two the infra-config skeleton registers. docs (also Next.js, and the only repo with
  PostHog today) is onboarded in v1 with the PostHog work.
- Execution on GitHub (merge queue + Actions), behind the executor interface so Launchpad can replace it
  later (D7).
- Only the canary channel is live. Dev is declared but off; stable and the installer are priority P4,
  low (D8).

**How to read the tables.** One row is one work item that can be handed to one owner, human or agent.
Owner is blank on purpose: suraj assigns owners (D11). "Done when" is a pass/fail test. IDs are stable,
so other items can depend on them. Items marked **admin** need org-admin rights.

**v0 exit test.** All of these hold at once:
1. All thirteen repos exist and are public, each with CODEOWNERS, a generated presubmit and a merge queue.
2. xo-space and innernet are gated from their `infra/repo.toml` manifests and the central builder
   definitions in `infra-config`, through shared adapters. A deliberately red PR is refused in each.
3. A daily canary of xo-space and innernet runs for 7 days in a row with no human touch. A planted bad
   canary is held, gets a failure record, and a rollback drill restores the previous canary in under 10 min.
4. A planted build-breaking commit is reverted automatically within the D5 caps, and the revert has a
   failure record that links culprit and fix.
5. Scorecard v0 is computed by a script, not typed.

## infra-config (infra as code)

**Baseline already built.** The v0 skeleton exists (this repo,
2026-10-03): one TOML file per area under `config/` (org, kinds, repos, pipelines, gate, flakes,
auto_revert, rollers, channels, fuzz, postmortem, health, perf), a JSON Schema per area under `schema/`,
and `tools/qqcfg.py` to validate and generate, with tests and a CI workflow. Builder definitions live
here centrally; product repos keep only their manifest (D15). It generates one example builder so far
(xo-space presubmit). Areas marked `stub` have shapes but placeholder values. Remaining v0 work:
